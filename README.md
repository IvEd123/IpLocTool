# IP Локация · Android

Лёгкое нативное приложение на Java и домашний виджет. Android 6.0+ (API 23), target API 35. Только Android SDK, без runtime-зависимостей, WebView, аналитики и рекламы. Release APK оптимизируется R8 и удалением неиспользуемых ресурсов.

## Установка

Откройте [Releases](https://github.com/IvEd123/IpLocTool/releases), скачайте `IpLocTool.apk` и разрешите установку из выбранного источника. `SHA256SUMS` содержит контрольную сумму APK.

Нажмите **Проверить IP** в приложении. Для виджета используйте **Добавить виджет** или меню виджетов лаунчера → **IP Локация**. В списке доступны компактный 2×1, средний 3×2 и большой 4×3; фактическая сетка зависит от лаунчера. Любой вариант можно растягивать — компоновка меняется по размеру, большой вариант дополнительно показывает провайдера. На Android 12+ переключение компоновки происходит на стороне лаунчера, на Android 6–11 — при изменении размера. Виджет показывает публичный IP, примерную страну/город и время проверки. Нажатие на информацию открывает приложение; отдельная кнопка выполняет проверку. Несколько виджетов используют один результат.

## Поведение и расход энергии

- Запрос только по кнопке в приложении или виджете. Открытие приложения, установка виджета, перезагрузка и изменение сети не выполняют запрос.
- Нет постоянной службы, будильников, WorkManager, периодических заданий, GPS и wakelock. По явному нажатию запускается короткая foreground-служба типа dataSync с уведомлением «Проверяем IP»; после результата/ошибки она удаляет уведомление и останавливается, `START_NOT_STICKY` не позволяет автоматический перезапуск. `updatePeriodMillis=0`.
- Система хранит RemoteViews виджета; держать приложение работающим не требуется. Кнопка виджета вызывает службу напрямую через `PendingIntent.getForegroundService()` (Android 8+) или `getService()` (Android 6–7). Сетевой запрос больше не зависит от короткого окна broadcast receiver и фоновых ограничений доступа к сети.
- Один короткий поток на запрос, HTTP-таймауты подключения/чтения 8 с и общий таймер запроса 20 с. Повторные нажатия во время проверки объединяются.
- Последний успешный результат и время хранятся локально в SharedPreferences. Приложение и виджеты синхронизированы. При ошибке старые данные сохраняются, ошибка показывается отдельно. Они могут устареть после смены сети/VPN — нажмите кнопку снова.
- После принудительной остановки в настройках Android может потребоваться открыть приложение для восстановления работы виджета.

## Данные

Один HTTPS-запрос к `https://ipwho.is/?lang=ru`, без API-ключа. Сервис видит публичный IP запроса; GPS и идентификаторы устройства не отправляются. Определяются IP (IPv4 или IPv6 по маршруту соединения), страна/регион/город и провайдер. Страна отображается также флагом. IP-геолокация приблизительна, зависит от базы сервиса, VPN и маршрутизации; она не определяет точное положение телефона. Доступность и лимиты зависят от ipwho.is; перед коммерческим использованием проверьте его актуальные условия. Это самостоятельное приложение с похожим на 2ip назначением.

## Сборка

Требуются JDK 17, Gradle **8.9**, Android SDK Platform 35 и Build Tools 35.0.0. Wrapper отсутствует: CI устанавливает фиксированную версию через `gradle/actions/setup-gradle`.

```sh
gradle testDebugUnitTest lintRelease assembleRelease
```

APK: `app/build/outputs/apk/release/app-release.apk`. Для обычной debug-сборки: `gradle assembleDebug`.

В CI выполняются JUnit-тесты разбора ответа (IPv4/IPv6, флаги, пропущенная локация, ошибки сервиса), выбора компоновки и сообщений об ошибках, Android Lint, release-сборка и проверка APK-подписи. Отчёты, APK и SHA256 загружаются в артефакты Actions.

## GitHub Actions и релизы

- Push в `main`: проверки, оптимизированный подписанный APK и Release `build-N`.
- Тег `v*`: те же проверки и Release с именем тега.
- Pull request: проверки и APK-артефакт, без публикации релиза и прав записи.
- Ручной запуск `Android APK`: можно отключить публикацию параметром `publish_release`.
- `versionCode` равен номеру запуска workflow, `versionName` — `1.0.N`. Теги не меняют версию внутри APK.

### Подпись

Без секретов CI использует временный Android debug-ключ и публикует устанавливаемый preview APK. Ключ не добавляется в репозиторий. На новом runner подпись меняется, поэтому для установки следующей сборки может потребоваться удалить предыдущую версию (с удалением её локального кэша).

Для постоянной подписи добавьте в **Settings → Secrets and variables → Actions**:

- `ANDROID_KEYSTORE_BASE64`: личный keystore в base64.
- `ANDROID_STORE_PASSWORD`: пароль keystore.
- `ANDROID_KEY_ALIAS`: имя ключа.
- `ANDROID_KEY_PASSWORD`: пароль ключа.

CI автоматически использует эти секреты для release APK. Сохраните резервную копию личного ключа вне Git; все будущие обновления требуют той же подписи. Для локальной production-сборки задайте переменные `IPLOC_KEYSTORE` (абсолютный путь), `IPLOC_STORE_PASSWORD`, `IPLOC_KEY_ALIAS`, `IPLOC_KEY_PASSWORD`. Переход с preview на постоянный ключ требует переустановки.

## Проверка на устройстве

Перед повседневным использованием проверьте на своём лаунчере: первую ручную проверку, виджет после закрытия приложения/перезагрузки, несколько экземпляров, ошибки без сети, три размера и растягивание виджета, повторные нажатия, смену VPN и увеличение шрифта. Смена сети сама проверку не запускает. Автотесты не заменяют проверку Android/лаунчера на устройстве.
